# Unix/Crypt.cpp

## Purpose
Darwin/Android implementation of RBX::Crypt using OpenSSL: SHA-1 over the message, base64-decode of the signature, PEM-parse of a hardcoded RSA public key, then `RSA_verify`. Mirrors the Win32 rbx/Crypt.cpp contract with a different crypto backend.

## API
```cpp
RBX::Crypt::Crypt();    // empty
RBX::Crypt::~Crypt();   // empty
void RBX::Crypt::verifySignatureBase64(std::string messageStr, std::string signatureStr);
     // throws std::runtime_error("") when verification fails
```
Internal helpers (anonymous namespace): `unbase64(char* input, unsigned char** out)` — OpenSSL BIO chain decode, caller frees; `verifyMessage(char* message, char* sig_b64)` — returns RSA_verify result (1 == valid).

## Usage
Selected for __APPLE__ i386 or __ANDROID__ via `RBX_BUILD_CRYPT`; other platforms hit `#error Unsupported platform.` Declared in include/rbx/Crypt.h. In-file comment credits key generation: "Public/Private Key Pair generated by Ben D".

## Gotchas
- DIFFERENT KEY than Windows: a PEM "BEGIN PUBLIC KEY" block here vs the CryptoAPI blob in rbx/Crypt.cpp — two independent public keys for the same verification role.
- On platforms compiling the file without RBX_BUILD_CRYPT (impossible per the #error, but the code paths exist), verifyMessage returns 1 — always-valid stub, same fail-open shape as the Win stub build.
- `unbase64` mallocs `strlen(input)` bytes (over-allocation by design, comment says so); `buffer[length]=0` writes one past BIO_read's count — within the malloc'd slack.
- SHA_CTX/RSA low-level OpenSSL APIs are long-deprecated in modern OpenSSL — relevant for the Luau/Wine x64 rebuild's dependency choices.
- Failure exception text deliberately empty: "message hidden on purpose - prevent reverse engineering".
