# App/script/LuaArguments.cpp

## Purpose

Implements the bidirectional Reflection↔Lua value marshaling layer: `RBX::Lua::LuaArguments` reads typed arguments off the stack (`getString/getVector3/getBool/...`), recursively converts arbitrary Lua values into `Reflection::Variant`s including nested tables (`get`/`getRec`), and `class ArgumentPusher` converts `Reflection::Variant`s back into Lua values via the `withVariantValue<int>` visitor. Every bridge, event fire, callback invocation, and tuple resume in the scripting stack funnels through this file.

## API

- `DYNAMIC_FASTFLAGVARIABLE(LuaCrashOnIncorrectTables, false)`.
- Instance readers (all take `int index`, offset by the ctor's `offset`, return false when `index > lua_gettop(L)` or type mismatches): `getString(int, std::string&)`, `getVector3int16(int, Vector3int16&)`, `getRegion3int16(int, Region3int16&)`, `getVector3(int, Vector3&)`, `getRegion3(int, Region3&)`, `getRect(int, Rect2D&)`, `getPhysicalProperties(int, PhysicalProperties&)`, `getObject(int, shared_ptr<Reflection::DescribedBase>&)` (nil → null shared_ptr; userdata → ObjectBridge::getPtr), `getDouble(int, double&)`, `getBool(int, bool&)`, `getEnum(int index, const Reflection::EnumDescriptor& desc, int& value)` (accepts EnumItem userdata of matching owner or a raw number validated with `desc.isValue`). The class also exposes ctor `LuaArguments(lua_State* L, int offset)` plus accessors like `count()` from its header.
- `static bool LuaArguments::get(lua_State *L, int luaIndex, Reflection::Variant& value, bool treatNilAsMissing)` — entry point wrapping `getRec` with a fresh `TablesCollection localTables(NULL)`.
- `static bool LuaArguments::getRec(lua_State*, int, Variant&, bool treatNilAsMissing, TablesCollection* visitedTables)` — number→double, boolean→bool, string→std::string; table→ either `shared_ptr<const Reflection::ValueArray>` (when `lua_objlen > 0`, filled 1..n via rawgeti recursion) or `shared_ptr<const Reflection::ValueTable>` (general traversal via lua_next, string keys only — "keys must be strings" otherwise); empty table → empty ValueArray ("they can auto-convert later"); cyclic tables throw "tables cannot be cyclic" (visited-pointer map, unmarked on exit for non-array branch); nil → false when treatNilAsMissing else void variant; function → `lua_tofunction`; thread/lightuserdata → void variant immediately (no bridge chain); unknown userdata → tries every bridge's `getValue` in a fixed order: Enums, ObjectBridge, CoordinateFrameBridge, Region3Bridge, Region3int16Bridge, Vector3int16Bridge, Vector2int16Bridge, Vector3Bridge, Rect2DBridge, Vector2Bridge, RbxRayBridge, Color3Bridge, BrickColorBridge, UDimBridge, UDim2Bridge, FacesBridge, AxesBridge, CellIDBridge, PhysicalPropertiesBridge, NumberSequenceBridge, ColorSequenceBridge, NumberRangeBridge, NumberSequenceKeypointBridge, ColorSequenceKeypointBridge; unmatched userdata falls through to void variant while still returning true (source carries "TODO: Shouldn't we return false?").
- `class ArgumentPusher` — visitor overloads returning pushed-value count: `operator()()` pushes nil; bool → lua_pushboolean; arithmetic T (enable_if is_arithmetic) → lua_pushnumber; std::string / ProtectedString (pushes `.getSource()`) / ContentId (toString) / PropertyDescriptor (name.toString) → strings; shared_ptr<Instance> → ObjectBridge::push; EnumDescriptor::Item → EnumItem::push; WeakFunctionRef/GenericFunction/GenericAsyncFunction → `lua_pushfunction`; shared_ptr<const Tuple> → recursive push of each value ("unpack", null tuple = 0 items); ValueTable/ValueMap → Lua table with string keys, NULL maps become EMPTY tables ("never return nil"); ValueArray/Instances → `LuaArguments::pushArray(begin,end,L)` (NULL becomes empty table); generic fallback template (disable_if arithmetic) → `Bridge<T>::pushNewObject`. The ValueTable path contains a `DFFlag::LuaCrashOnIncorrectTables` guard that RBXCRASHes if a push doesn't add exactly one stack slot.
- `static int LuaArguments::push(const Reflection::Variant&, lua_State* const L)` — `withVariantValue<int>(value, pusher)`.
- `static int LuaArguments::pushReturnValue(const Reflection::Variant&, lua_State*)` — void variant pushes nothing (0), else push.
- `static shared_ptr<Reflection::Tuple> LuaArguments::convertToReturnValues(const Reflection::Variant&)` — void → Tuple(0), else single-element Tuple(1).
- Also referenced here from the header: `pushTuple(const Tuple&, lua_State*)`, `getValues(lua_State*)`, `pushArray(...)`.

## Usage

Callers span the whole module: `ScriptContext` uses pushTuple/pushReturnValue/readResults-style gets for thread resumes; `LuaInstanceBridge` builds `LuaArguments args(L, 1)` for member-function calls and calls `pushReturnValue(args.returnValue, L)`; `LuaSignalBridge` pushes event argument tuples via `LuaArguments::pushValues(arguments, thread)`; `ThreadRef.cpp`'s GenericFunction bridge collects args with `LuaArguments::getValues(L)`. It depends on every atomic-class Bridge (App/script/LuaAtomicClasses.cpp), `EnumItem`/`Enums` (App/script/LuaEnum.cpp), `ObjectBridge` (App/script/LuaInstanceBridge.cpp), and `lua_tofunction/lua_pushfunction` (App/script/ThreadRef.cpp).

## Gotchas

- Table conversion is asymmetric: positive-length tables become ValueArrays keyed 1..n regardless of key content; zero-length or string-keyed tables become ValueTables; empty tables always come back as ValueArrays. Round-tripping `{a=1}` yields a ValueTable, but `{}` yields an empty ValueArray — scripts observing `type()` differences across engine boundaries can detect this.
- Cycle detection is asymmetric in a subtle way: EVERY table checks-and-marks the visited-pointer map on entry (`if (visited) throw "tables cannot be cyclic"`), but only the general-table (map) branch unmarks on exit. A table processed as an array stays marked for the rest of the `get()` call — so referencing the same array-shaped table twice (e.g. `{t, t}`) raises a spurious "tables cannot be cyclic", while genuinely cyclic arrays do throw correctly on re-entry.
- Unrecognized userdata silently becomes nil/void with `return true` (explicit TODO questioning it) — typos in userdata types vanish rather than erroring at this layer.
- `treatNilAsMissing` implements TrailingNilParameters semantics (referenced lua-users wiki link): trailing nils truncate the argument list for optional-parameter reflection functions.
- ArgumentPusher's ValueTable crash guard exists specifically because a misbehaving Bridge::pushNewObject could corrupt stack accounting during settable — enabled only under DFFlag::LuaCrashOnIncorrectTables.
- ProtectedString values are pushed as their raw source text with no sandbox marking.
