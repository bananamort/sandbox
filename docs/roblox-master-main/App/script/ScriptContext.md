# App/script/ScriptContext.cpp

## Purpose

The heart of the Roblox scripting stack. `ScriptContext` is an `Instance` (ServiceProvider child, name "Script Context") that owns one `lua_State` "global state" per security VM tier, creates/sandboxes/resumes all Lua threads, defines the engine-provided globals (`game`, `wait`, `spawn`, `pcall`, `require`, `loadstring`, ...), runs the GC and waiting-script scheduler jobs, enforces script timeouts, and implements the module (`ModuleScript`) require/reload machinery. The file also contains the large "Lua SECURITY" comment block (lines 102–180) that enumerates exactly which standard-library entry points are SANDBOXED/PROTECTED/LOCKED/OVERRIDEN/SUPPRESSED/NOT LOADED — the canonical statement of the 5.1 sandbox model that a Luau graft must reproduce. A second class, `RuntimeScriptService` ("RuntimeScriptService"), lives at the bottom of the file and gates which scripts run as simulation starts/stops.

## Usage

Called from above by the DataModel/service lifecycle: `ScriptContext::onServiceProvider` creates all states (`openState(i)` per VM tier) when a provider attaches and tears them down (`closeStates(false)`) when it detaches; it also connects `RunService::heartbeatSignal` → `onHeartbeat`, registers `GcJob` and `WaitingScriptsJob` with `TaskScheduler`, and installs the ckey (`LUAVM_KEY_DUMMY` when `LuaVM::canCompileScripts()`, else `LuaVM::getKeyCore()` into the privileged VM). `BaseScript` instances reach this file through `RuntimeScriptService::runScript/releaseScript` and `ScriptContext::addScript/removeScript/startScript`; `CoreScript` fetches source via `CoreScript::fetchSource("Libraries/"+name)` in `loadLibrary`. Downward, everything goes through the patched Lua 5.1 C API and engine helpers: `LuaVM::load(thread, ProtectedString, chunkname [, modkey])` is the only compile path; `ObjectBridge::push` marshals instances; `LuaArguments::pushTuple/get/getValues` marshal tuples; `Lua::LibraryBridge::find/saveLibraryResult/registerClass/LibraryBridge` implement LoadLibrary caching; `WeakThreadRef/ThreadRef/WeakThreadRef::Node::create` manage thread lifetime; `RobloxExtraSpace::get(L)` carries per-thread `identity`, `script`, `continuations`, `yieldCaptured` and back-pointer `context()`. Errors flow out through `reportError` → `StandardOut`, optional `Stats::StatsService::report("LuaExceptions", ...)`, the `Error` reflection event, `scriptErrorDetected`, and `BaseScript::extraErrorReporting`.

## Gotchas

- `sandboxThread` (lines 1249–1273) is the entire environment-isolation mechanism: a fresh empty globals table whose metatable has protected `__metatable` and `__index` pointing at the *previous* `LUA_GLOBALSINDEX` table, installed with `lua_replace(thread, LUA_GLOBALSINDEX)`. There is no `setfenv` usage anywhere here; every sandboxed thread gets its own chained table. Writes to globals stay local because `__newindex` is not set up to forward — new writes land in the shadow table.
- All resumes go through `resumeImpl` (line 3506). With `DFFlag::ScriptContextGuardAgainstCStackOverflow` it maintains a thread-specific depth counter (`kCLuaResumeStackSize`, >200 throws "C stack overflow") around `lua_resume(L, nargs)` — relevant to grafting because Luau's resume path differs.
- Continuations are dispatched inside `ScriptContext::resume(ThreadRef,int)` immediately after `resumeImpl` returns: Error → `continuations->error(thread)`; Success → `continuations->success(thread)` with exceptions converted into error-continuation invocations after pushing `e.what()`. A `LUA_YIELD` result queues the waiter via `yieldEvent->queueWaiter(thread)` unless `RobloxExtraSpace::get(thread)->yieldCaptured` is set (set by `ypcall`, module require, etc. that capture yields themselves).
- Two VMs in practice (`VM_Default`, `VM_RobloxScriptPlus`, plus `VM_StudioPlugin` under RBX_STUDIO_BUILD); `getGlobalStateIndex` deliberately separates user scripts from Roblox scripts "not mixing user scripts with ROBLOX scripts". Identity→VM mapping happens once at thread creation.
- `pcall` is replaced by `ypcall`; `ypcall`'s Yield case installs continuations onto the *functor* thread and marks the *caller* thread `yieldCaptured`, then yields the caller — transparent yielding across pcall boundaries. `load` is `notImplemented`; `dofile` throws; `loadfile` requires `Security::LocalUser`, `Network::isTrustedContent` ("invalid request 5"), fetches over HTTP and demands `ContentProvider::verifyScriptSignature(source, true)`; `loadstring` is gated server-side by `ServerScriptService::getLoadStringEnabled` and client-side refused unless CloudEdit and `LuaVM::canCompileScripts()`.
- Bytecode security: `l_G->ckey` per global state (`setKeys`, `onServiceProvider`), `LUAVM_MODKEY_DUMMY` vs server-supplied `coreScriptModKey` chosen in `loadLibrary` depending on whether the target VM is the privileged one — loading core-script bytecode into the normal VM requires the modkey transform from the server packet.
- Anti-tamper: `executeInNewThread` contains an xxhash self-check block (`kIntermediateGolden == 976374109`, `kGolden == 0xCDF961F8`, sets `HATE_XXHASH_BROKEN` hack flag, guarded `_WIN32 && !RBX_STUDIO_BUILD`, wrapped in `VMProtectBeginMutation("3")`), a CheatEngine check that flags `HATE_ILLEGAL_SCRIPTS` if the current thread lacks the DataModel write lock, and `onServiceProvider` wraps a `securityAnchor.update(&securityAnchor)` self-check in `VMProtectBeginVirtualization`. `preventLinkerStrip` forces references to the lua debug-API symbols so they survive linking.
- `openState` reassigns `_G` to a brand-new empty table (explicitly noted as "a breaking change to Lua's spec") and loads libraries via `loadLibraryProtected`, which calls `lua_setreadonly(L, -1, true)` — a custom 5.1 patch (readonly tables are not stock Lua).
- Module require semantics: `require(number)` is forbidden on clients ("cannot be called from a client"); remote modules arrive via `ContentProvider::loadContent` + `LuaSourceContainer::loadLinkedScriptsForInstances`, expect an instance tree containing a child named exactly `MainModule`; yielded importers are parked either in `AssetModuleInfo::yieldedImporters` or `ModuleScript::PerVMState` and resumed with the registry ref of the module result. `info.state` is set to Fetched *before* running the module so a reentrant require during execution doesn't double-run it.
- Module hot-reload patches results in place: `reloadModuleScriptInternal` runs a fixed Lua snippet (`oldResult, moduleRef = ...` … copies keys from `newResult` into the old table and deletes keys absent from the new) so existing holders of the old table see updated contents; if the module is still Running the reload is deferred via `setReloadRequested(true)` and retried from the success/error continuations.
- Timeout model: a dedicated boost thread (`onCheckTimeout`) flips atomic `timedout` and increments `timedoutCount`; `LUA_HOOKCOUNT` (every `hookCount`=1000 instructions) checks it; `onHook` errors only for identities `GameScript_`/`RobloxGameScript_`; `onHeartbeat` resets `timoutTime` every beat and decrements the count — i.e., timeout windows restart each Heartbeat.
- `startScript` re-entrancy is capped at 3 (throws beyond); scripts whose code isn't loaded yet (`requestCode().loaded == false`) are silently skipped and retried by `startPendingScripts` once per Heartbeat second; `loadingScripts` start even when `ScriptsDisabled` is true (they're CoreScripts).
- `doPrint` writes `' '` separators into the returned message but emits literal `'\t'` to stdout between arguments (adapted from `luaB_print`).
- `cleanTimeout` clamps any wait/delay below `LuaSettings::singleton().defaultWaitTime` up to that value, and also sanitizes NaN/inf (second branch effectively catches inf since negatives hit the first branch).
- `getGlobalState(lua_State*)` compares `global_State` pointers (`iter->state->l_G == thread->l_G`) rather than identity of the state — correct across coroutines but returns NULL for threads created under a foreign context.
- `validateThreadAccess` crashes (`RBXCRASH`) instead of asserting when `DFFlag::LockViolationScriptCrash` is enabled and the DataModel write lock is missing.
- `addStarterScript`/`AddCoreScript` are disabled except for two hardcoded PBS/build-mode asset hacks (124885177 → CoreScripts/BuildToolsScripts/PersonalServerScript; 59431535 → BuildToolsScript).
- `RuntimeScriptService` holds scripts in pending/running sets keyed by `weak_ptr<BaseScript>`; CoreScripts bypass it entirely ("start and forget"), and the code comments concede "This whole CoreScript running code is a mess".
