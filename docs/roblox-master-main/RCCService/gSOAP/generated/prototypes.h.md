# prototypes.h

Source: `roblox-sandbox/RCCService/gSOAP/generated/prototypes.h` (2794 lines)

## Purpose

The **wsdl2h output** and soapcpp2 *input*: an intermediate gSOAP header spec translating `RCCService.wsdl` into C++-flavored service definitions. Header line 2 pins its provenance precisely: *"Generated by wsdl2h 1.2.10 from RCCService.wsdl and typemap.dat, **2018-02-23 23:46:17 GMT**"* — i.e., this checked-in tree was regenerated from the original WSDL shortly before Roblox's 2018 open-source release. Its own NOTE block warns: **"DO NOT include this file directly into your project"** — it exists only to be fed to soapcpp2 (which produced soapStub.h / soapH.h / service files).

## API

### Namespace + imports

`#import "stlvector.h"` (43); prefix binding `ns1 = "http://roblox.com/"`, elementForm qualified, attributeForm unqualified (62–64). A NOTE recommends customizing prefixes via typemap.dat.

### Type section (74–713)

- Forward declarations for all six data classes and all 36 message-element classes.
- `enum ns1__LuaType { LUA_USCORETNIL … LUA_USCORETTABLE }` (202–209) mapping to strings `"LUA_TNIL"` etc.
- Data classes in *spec* syntax — occurrence digit after each member (`0` optional / `1` required), e.g.:

```cpp

{ public:
    std::string    id                   1;   ///< Required element.
    double         expirationInSeconds  1;
```

Full set mirrors soapStub.h exactly: `ns1__Status`, `ns1__Job`, `ns1__ScriptExecution`, `ns1__ArrayOfLuaValue`, `ns1__ArrayOfJob`, `ns1__LuaValue`; then `_ns1__<Op>` / `_ns1__<Op>Response` ×18 with identical members (vectors marked `0..unbounded` or `1..unbounded`).

### Services section (715–2793)

Then per operation (×2 bindings) a Doxygen page plus the actual declaration, e.g. (854–860):

```cpp
//gsoap ns2  service method-encoding:	HelloWorld literal
```

Each Doxygen block also sketches what soapcpp2 will generate: client stub `soap_call___ns2__<Op>(soap, endpoint, action, req, resp)` and server function `__ns2__<Op>(soap, req, resp)`.

## Usage

Consumed exclusively by generate.bat step 2: `soapcpp2 -x -i -S -Iimport -dgenerated generated/prototypes.h`.

## Gotchas

- The occurrence digits are soapcpp2 annotations, not valid C++ — compiling this file directly fails.
- The generation date (2018) postdates the license headers of the vendored import stubs (~2005) — tools were newer than most shipped files.
- Because `-S` is used downstream, the documented client-stub/proxy code in the comments is never generated here.
- No endpoints exist (matching the WSDL's missing `<wsdl:service>`): the "Endpoints" sections are empty placeholders noting wsdl2h option `-N`.
