# c14n.h

Source: `roblox-sandbox/RCCService/gSOAP/import/c14n.h` (25 lines)

## Purpose

gSOAP *import* stub that declares the W3C **Exclusive XML Canonicalization** (exc-c14n) schema namespace `http://www.w3.org/2001/10/xml-exc-c14n#` to `soapcpp2`. It reaches the security headers transitively (`wsse.h` imports `ds.h`, which `#import`s `c14n.h` at its line 72), so canonicalization elements can appear inside signed/encrypted SOAP messages. In the RCCService tree it exists only as part of the vendored gSOAP import library; nothing in the service's own WSDL (`RCCService.wsdl`) uses the `c14n` prefix.

## API

One generated-schema struct (gSOAP directive comments at lines 13–15 declare the schema binding: namespace `http://www.w3.org/2001/10/xml-exc-c14n#`, elementForm `qualified`, attributeForm `unqualified`):

```cpp
typedef struct _c14n__InclusiveNamespaces
{	@char*				PrefixList;
} _c14n__InclusiveNamespaces;
```

- `_c14n__InclusiveNamespaces::PrefixList` — the `@` marks it as an XML *attribute*, not an element; a whitespace-separated list of namespace prefixes to be treated as inclusive during canonicalization.
- There are no functions; gSOAP serializes/deserializes the struct automatically once the type is reachable from an operation signature.

## Usage

Not referenced by RCCService code or by `RCCService.wsdl`; it ships with the toolchain because `wsse2.h`-style WS-Security flows need it when messages are canonically serialized before signing:

```
#import "c14n.h"        // in a gSOAP .h spec file, alongside wsse.h
soapcpp2 -Iimport myservice.h
```

## Gotchas

- The file is almost entirely absent of code — 1 typedef after license/schema directives; any expectation of c14n *implementation* here is wrong (the algorithm lives in the gSOAP plugin runtime, not this header).
- The trailing `#` in the namespace URI is part of the official exc-c14n namespace name.
- Because `elementForm: qualified`, generated element names carry the `c14n__` prefix in soapStub.h if the schema is ever pulled into a compile.
