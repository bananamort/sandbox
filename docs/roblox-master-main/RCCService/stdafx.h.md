# stdafx.h

Source: `roblox-sandbox/RCCService/stdafx.h` (51 lines)

## Purpose

Precompiled-header umbrella for the RCCService project: Windows/ATL configuration macros plus the handful of external headers every TU wants. Generated by the VS wizard, then hand-edited with engine-specific additions.

## API

Macro configuration:

- `STRICT`, `NOMINMAX`, `_CRT_SECURE_NO_WARNINGS 1`, `WIN32_LEAN_AND_MEAN`
- ATL: `_ATL_CSTRING_EXPLICIT_CONSTRUCTORS`, `_ATL_APARTMENT_THREADED`, `_ATL_NO_COM_SUPPORT` (project exports no COM objects)
- Targeting: `_WIN32_WINNT 0x0501` (XP), `WINVER`/`_WIN32_WINDOWS` mirror it, `NTDDI_VERSION 0x05010100` (`NTDDI_WINXPSP1`), `_WIN32_IE 0x0601`
- Engine shims: `NO_SDL_MAIN` (suppress SDL's main redefinition), `G3DEXPORT = __declspec(dllimport)` (consume g3d as a DLL)

Includes: `<sdkddkver.h>`, `<atlbase.h>`, `<atlstr.h>`, `<atlcom.h>`, `<atlutil.h>`, `<string>`, `<boost/asio/error.hpp>`.

## Usage

Included first (via `stdafx.cpp` PCH build) by every `.cpp` in this folder.

## Gotchas

- The XP-era targeting macros (`0x0501` family) are defined **before** `<sdkddkver.h>` is included; sdkddkver normally derives these itself, so the explicit values win only because they come first — a fragile ordering.
- `WIN32_LEAN_AND_MEAN` + `NOMINMAX` mean TUs must pull in anything beyond the lean set explicitly; `ATL` headers are mandatory here (e.g., `CRegKey` used in `RCCService.cpp` comes from `atlbase.h`).
- Boost asio error header included for its error codes though no sockets live in this folder directly (gSOAP uses raw Winsock).
- Wizard TODO comments left intact (lines 33–37, 51).
