# Plan: WS4 Luau Graft — correct, not stubbed, no revert

> **HARD CONSTRAINT (user, 2026-08-27):** A revert to pass CI is a hard prohibition. The graft must make both build AND runtime correct. No stubs that compile away, no lua_Pushcfunction-debug-name layers that fake the API, no method stubs that return `nullptr` to satisfy the linker. Every bridge shim must produce runtime behavior the engine actually uses.

> Baseline: `main` at `29562f5f2` is Lua 5.1.4 + green (run `33030487767` two-sided smoke). `ws4-luau` branch at `5dbd6c1c5` has the C1+C2 attempts (Luau 0.735 vendored, App.vcxproj wired, shim headers, luaconf merge) but is red. Branch tip is the foundation to land C3-C7 onto.

> Why the previous attempt failed and why the **fix is** the work: every Luau diff between 5.1 and current (lua_Debug fields, RobloxExtraSpace, LuaVM::load → luau_load, lua_resume(from), ENVIRONINDEX removed, LUA_QS gone) is **load-bearing** for `openState/sandboxThread/resumeImpl/startScript/loadstring`. Stubbing them green-lights a build that would crash on the first `script.Run()` call. The graft has to provide **working implementations** in terms of Luau's public API, not glue over missing methods.

## Strategy: three-line bridge layer, real implementations only

For each Luau API the engine uses, write a single **adapter header** under `App/Lua-5.1.4/src/` (`robloxlua_compat.h` plus per-feature sub-headers) that exposes the same surface as the 2016 5.1.4 calls but routes through Luau's real API. The adapter is what engine code `#include`s; the engine source is **not** rewritten wholesale. This is mechanical, can be reviewed per-file, and is verifiable: every call site is a known 5.1.4 call, the adapter is a known Luau function. **No edit is acceptable that produces a no-op stub of a called method.**

Hard rules:

- Every adapter method is implemented, not stubbed. If a 5.1.4 method has no exact Luau equivalent, the adapter picks the closest Luau primitive and an inline comment cites why.
- Existing `RobloxExtraSpace` shim that returns `nullptr` and `LuaVM::canCompileScripts() { return true; }` and `LUA_QS` placeholder are **deleted and replaced with real definitions**, in the same commit.
- No "compile-clean" intermediate state is committed. If a commit is green on build but the smoke would fail, the commit is wrong.
- If a `RobloxExtraSpace` field can't be remapped in the current commit, the engine call sites are modified (or the field becomes a side-table), not stubbed.

### C3 — extra space (RobloxExtraSpace, identity, yieldCaptured, continuations)

This is the load-bearing commit. The previous attempt stubbed it — that is the **root cause** of the smoke failure. The actual graft is real:

- `App/Lua-5.1.4/src/robloxlua_extraspace.h` — defines `RBX::RobloxExtraSpace` as a real C++ struct that fits in Luau's `LUAI_EXTRASPACE` (16 bytes; can be enlarged via `lua_setextraspace` style API or a side-table). Fields: `identity:5`, `yieldCaptured:1`, `script` (weak_ptr), `continuations*`, `node` (intrusive_ptr). Provides `get(lua_State*)` that uses `lua_getextraspace` to obtain a real per-thread pointer. **This is not a stub — it returns a real pointer to real data per thread.**
- `lstate.c` shim: `luai_userstateopen/close/thread/free/resume/yield` hooks in Luau's `luaconf.h` route to the RobloxExtraSpace lifecycle (via `#define` of the hook names). When a `lua_newstate` runs, the constructor `setContext(this)` fires. When a thread is created, the child's shared pointer is copied. When a thread is closed, the destructor unlinks it. **Verified by running smoke and observing `RobloxExtraSpace::get(L)->context()` returns a non-null `ScriptContext*`.**
- Identity / script / continuations are stored in `extraspace` (struct field layout) — no global side-table, no map lookups. The `script` weak_ptr is a 2016-specific RBX wrapper; we vendor `WeakThreadRef::Node` definitions and use real `boost::weak_ptr` plus intrusive list hooks as 2016 did.
- Tests added: `RobloxExtraSpace::get(L)->script` matches the thread's owner; `yieldCaptured=true` set/cleared around `lua_yield` via a per-call shim wrapper (`luaB_yield_capture` in our adapter, replacing the manual `YieldingThreads` priority queue for the actual VM — see C7).

### C4 — pushcfunction debug-name (121 sites)

- Codemod `lua_pushcfunction(L, fn)` → `lua_pushcfunction(L, fn, "fn")` using `__LINE__` from a Python script in `tools/codemod_pushcfunction.py`. 121 sites in `App/script/{ScriptContext, LuaAtomicClasses, LuaSignalBridge, LuaBridge, LuaLibrary, LuaEnum, DebuggerManager}*.cpp`. Each call site gets a real debugname string (function name from the parent class or a meaningful string), not an empty string.
- Verifier: after codemod, `grep -c "lua_pushcfunction(L,"` returns 0; `grep -c "lua_pushcfunction(L, .*, " returns 121+1 (one site in `ci_atl_loader_shim.h` shim).
- **The previous attempt did not do this codemod and was satisfied with the Luau-mandated 2-arg form silently working. The 2-arg form is mandatory in Luau (no default); skipping C4 means the engine is calling the macro with the wrong arity, which on some hosts compiles to a wrong symbol. The codemod is what makes it correct.**

### C5 — resume(from) at resumeImpl:3506

- Single edit at `ScriptContext.cpp:3506 resumeImpl`: `lua_resume(L, nargs)` → `lua_resume(L, /*from=*/NULL, nargs)`. We have no parent thread for these resumes (top-level `script.Run`); `from=NULL` is correct per Luau's API (single-threaded coroutine use). Multi-threaded cases (`lua_resume(co, parent_co, nargs)`) appear nowhere in 2016's host code per `docs/roblox-master-main/App/script/ScriptContext.md` (sandboxThread uses a single coroutine per script). **C5 is one line of code in the single funnel; the entire graft's resume semantics turn on this change being exactly right.**
- The `DFFlag::ScriptContextGuardAgainstCStackOverflow` block continues to work — it runs before `lua_resume` so its depth counter is unaffected.

### C7 — yield continuations → Luau native, retire YieldingThreads storage — scheduler gate

- This is where the engine really uses RobloxExtraSpace. Homegrown `Lua::Continuations` (ScriptContext.cpp:1397-1524) and `YieldingThreads` (ScriptEvent.cpp) get replaced by:
  - Real `lua_yield` + Luau continuation via the `lua_CContinuation` callback param of `lua_pushcclosurek`. For each yieldable C function (LuaInstanceBridge's `YieldFunctionDescriptor::execute`, etc.), the adapter `yield_capture` calls `lua_yield(L, 0, &continuation, NULL)`. The continuation is invoked when the coroutine resumes.
  - The `yieldCaptured` flag moves from `RobloxExtraSpace` field to a thread-local in the adapter (it does not need cross-thread visibility — only the yielding thread inspects it).
  - `YieldingThreads::queueWaiter` (`ScriptEvent.cpp:23`) keeps its storage but becomes an **observer** that records (delay, monotonic deadline) for the instrumentation stream; it no longer drives resume, which is now Luau's job via the continuation.
  - `YieldingThreads::resume` (`ScriptEvent.cpp:43`) is similarly a passive observer; the actual resume fires the continuation.
- Scheduler gate: a test script `tests/era_corpus/wait_yield.lua` (`wait(0)`, `wait(0.1)`, `spawn(function() return print("x") end)`, `delay(0)`, `pcall(function() coroutine.yield() end)`, `coroutine.wrap(f)(...)`) prints deterministic order; both 5.1.4 and Luau must produce the same output.
- **Critically: this commit MUST pass the two-sided smoke. If `wait()` doesn't return, the client never reaches `Document::Start`; if it returns the wrong value, scripts return mismatched results and the smoke shows it.** Smoke-green is the gate, not link-green.

## Smoke gate is mandatory for C2-C7 — different from before

`build.yml::validate::Two-sided smoke` must remain green after every commit on `ws4-luau`. The previous attempt's "build green = done" stance is forbidden: a stubbed `LuaVM::canCompileScripts() { return true; }` compiles but `startScript` then fails to actually compile anything. The smoke is the truth.

If a commit breaks smoke, the path is:

1. Diagnose from the smoke stderr/stdout (the step captures both).
2. Fix the adapter (real implementation, not a stub).
3. Re-push. **No revert.**

The only acceptable reason to drop a commit is if a future graft commit supersedes it (e.g. C2 with old shim merged into C3 with new shim). Even then the dropping commit must have its smoke restored by the superseder in the same push.

## WS5 — Instrumentation (7 spine, single C-level stream) — starts after WS4 green

**Why C-level, not Lua-level (unveilr contrast):** The reference `unveilr` (thee-bot/unveilr) instruments **at the Lua layer from inside an executor**. It redefines `getfenv/setfenv`, wraps `fenv` with `__index/__newindex` metamethods that `Spy()` every global get/set, tracks `Variables[]/Internal[]/Types[]`, reconstructs an AST via `AstLib`, and hooks bytecode via `hookOp` (lute/lune `luau.compile` wrapper). See `unveilr/hook.lua` (fenv spy), `main.luau:1-100` (AST rebuild, `EnvLog`, `ToAST`), `notes.md` (catalog of per-obfuscator workarounds). This is powerful but **detectable and per-obfuscator**: `notes.md` lists >30 quirks — MoonSec detects C functions via `setfenv(func,{})` not erroring, Luraph crashes on `setfenv(fenv)` hooking, MoonVeil needs `CHECKINDEX` fix, Luraph tostring==45195195 breaks if `loadstring` error text is wrong, etc. Each obfuscator (Luraph custom VM, MoonSec/V, Prometheus) needs a separate workaround. Our approach is the inverse: **hooks live in C++ below Lua, indistinguishable from the implementation, zero blind spots**. A Luraph VM is itself Lua code running inside our Luau VM — every one of its instructions is a captured Luau instruction regardless of nesting depth. No `setfenv` to probe, no `hookfunction` to detect, no per-obfuscator decoder.

**Single-stream design:** One `tools/capture_stream.py` JSONL sink, not 7 files. Each hook emits `{seq, ts_ms, thread_id, hook:"openState|startScript|vmBridge|signal|instance|http|scheduler|forced", arity, args_hash, result}` with atomic `seq` in `ScriptContext` extraspace (`RobloxExtraSpace` after WS4). Deterministic replay for WS6/Wine and WS7/E2E; avoids interleaving bugs. If hook fails → `RBXCRASH`, never silently drop — Arch Dec 11.

**Forced coverage (post-quiesce):** After scheduler quiesce (`YieldingThreads` empty + heartbeat idle 200ms), bounded pump (500 firings / 5s): (a) walk the `SignalBridge` connection log and `dataModel->submitTask(bind(doEventFire))` every recorded `Connect` with one synthetic arg, (b) walk `Instance` registry and `ScriptContext` registry for every closure created but not yet fired and `resume` it. Both feed the *same* single stream — no second log. This is why unveilr's `ToExplore` deferred queue (main.luau `Iterate()`) is unnecessary: at C level we already have the connection list.

**Gate:** `instrumentation-smoke` CI job runs RCC+Client with `tests/era_corpus`, asserts `capture_stream.jsonl` has ≥1 record per spine + `forced` section, `signal` connect count == fire count (events that never fired go to forced), and `http` records byte-match `logging_proxy.log` (same truth, two witnesses).
